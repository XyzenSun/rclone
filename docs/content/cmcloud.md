# {{< icon "fa fa-cloud" >}} China Mobile Cloud (中国移动云盘)

China Mobile Cloud (中国移动云盘, formerly 和彩云) is the personal
cloud storage service of China Mobile, accessed here through the
IDaaS open platform API (openapi.yun.139.com V3 gateway). This is
the channel used by third-party agent applications, not the private
web API.

Paths are specified as `remote:path`, and may be as deep as required,
e.g. `remote:directory/subdirectory`.

## Root directory and access scope

The root of a `cmcloud:` remote is always the **agent dedicated
directory** that China Mobile creates when the authorization is
granted (located at `AI空间/第三方智能体/<agent>` in the personal
cloud). There is no `root_folder_id` option: the platform rejects
any write outside the dedicated directory with error 16110013, so
exposing such an option would only invite failures. `cmcloud:subdir`
addresses a path inside the dedicated directory.

The dedicated directory is bound to the device identity (`claw_uid`)
used during authorization: keep `claw_uid` unchanged and the
directory stays the same across re-authorizations.

## Configuration

Here is an example of making a remote for China Mobile Cloud.

First run:

```console
rclone config
```

This will guide you through an interactive setup process. The wizard
generates a device identity, then shows an authorization page URL:

```text
config_auth_wait>
```

Open the URL in a browser, sign in with the China Mobile account
that owns the files and approve the authorization. **The page must
reach its final success message** - a page that only says
"authorized" midway is not enough, and the wizard will keep asking
until the server confirms completion. Then return to rclone and
press Enter.

If you are configuring rclone on a remote machine without a browser,
forward the URL to a machine with one and complete the authorization
there. There is no headless (`--non-interactive`) authorization path;
the long-term `access_token` stored in the config can be copied to
another machine together with `claw_uid` if needed.

### Token lifetime

The wizard stores a long-term `access_token` (and the `claw_uid` it
is bound to) in the config file. Short-lived business tickets are
acquired automatically at runtime and refreshed transparently. If
the long-term token expires, re-run `rclone config` on the remote:
the wizard re-validates it silently when it is still valid and only
starts a new authorization when it isn't.

## Modified time and hashes

The modification time can only be set when uploading a file: rclone
sends it with the upload and reads it back with millisecond
precision. The modification time of existing files can't be changed
afterwards.

The backend provides SHA-256 hashes as reported by the platform, so
`--checksum` comparisons work.

## Limitations

The platform's open channel for agent applications has hard
restrictions, all verified against the real service:

- **No delete, no move, no rename.** The corresponding endpoints are
  blocked server-side for this credential (error 01000005), so
  `rclone delete`, `rclone purge`, `rclone move` and
  `rclone moveto` do not work. `rclone sync` without `--delete`
  works, but the destination accumulates files.
- **No overwrite.** Uploading to a path where a file already exists
  fails with an explicit error instead of overwriting (the platform
  has no overwrite mode and no delete to work around it). Server-side
  copy to an existing name is likewise rejected.
- **Server-side copy keeps the name.** `rclone copyto` with a
  different target name falls back to upload+download; copying into
  a different directory with the same name uses the server-side
  path.
- **Dedicated directory only.** Reads outside the dedicated
  directory are not attempted; writes there would be rejected by the
  platform anyway.

### Advanced options

Here are the Advanced options specific to cmcloud (China Mobile Cloud (中国移动云盘)).

#### --cmcloud-upload-cutoff

Cutoff for switching to multipart upload (>= 5 MiB).

Properties:

- Config:      upload_cutoff
- Env Var:     RCLONE_CMCLOUD_UPLOAD_CUTOFF
- Type:        SizeSuffix
- Default:     5Mi

#### --cmcloud-chunk-size

Chunk size for multipart upload (>= 5 MiB).

Files larger than upload_cutoff are split into chunks of this size. The number of parts is capped at 100; larger files get proportionally larger parts.

Properties:

- Config:      chunk_size
- Env Var:     RCLONE_CMCLOUD_CHUNK_SIZE
- Type:        SizeSuffix
- Default:     32Mi

#### --cmcloud-encoding

The encoding for the backend.

See the [encoding section in the overview](/overview/#encoding) for more info.

Properties:

- Config:      encoding
- Env Var:     RCLONE_CMCLOUD_ENCODING
- Type:        Encoding
- Default:     Slash,LtGt,DoubleQuote,Colon,Question,Asterisk,Pipe,BackSlash,Del,Ctl,LeftSpace,RightSpace,RightPeriod,InvalidUtf8,Dot

#### --cmcloud-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_CMCLOUD_DESCRIPTION
- Type:        string
- Required:    false
