# WoPan (China Unicom Cloud Disk)

WoPan (联通云盘, [pan.wo.cn](https://pan.wo.cn/)) is the cloud storage service
of China Unicom.

Paths are specified as `remote:path`, and may be as deep as required, e.g.
`remote:directory/subdirectory`.

## Configuration

Here is an example of making a remote for WoPan.

First run:

```console
rclone config
```

This will guide you through an interactive setup process. After selecting
`wopan` as the storage type, the wizard asks how to authenticate:

```text
Select how to authenticate
Choose a number from below, or type in your own string value.
 1 / Log in with phone number, password and SMS verification code
   \ (login)
 2 / Paste a refresh_token captured from the web page (access_token is optional)
   \ (token)
config_auth_method>
```

### Phone number login

Choose `login` and enter your phone number and password (the password is used
once to log in and is not stored). China Unicom then sends an SMS verification
code to your phone:

```text
config_auth_method> login

config_phone> 13XXXXXXXXX

config_password> (hidden)

config_sms_code> 123456
```

On success the wizard stores `access_token` and `refresh_token` in the config
file. Tokens are refreshed automatically while rclone runs, and the refreshed
tokens are written back to the config file.

### Pasting a refresh token

Alternatively, if you have captured a `refresh_token` yourself (for example
from the web page), choose `token` and paste it. You may also paste the
matching `access_token`; if left empty, rclone fetches a new one with the
refresh token on first use.

```text
config_auth_method> token

config_refresh_token> (hidden)

config_access_token> (hidden, may be empty)
```

### Advanced options

Here are the Advanced options specific to wopan (WoPan (China Unicom Cloud Disk)).

#### --wopan-family-id

Family Cloud ID.

Leave empty to use your personal cloud. Set this to switch to the
family cloud of the given ID.

Properties:

- Config:      family_id
- Env Var:     RCLONE_WOPAN_FAMILY_ID
- Type:        string
- Required:    false

#### --wopan-root-folder-id

ID of the root folder.

Leave blank normally. Fill in to use a non-root folder as the starting point.
Defaults to "0", the root folder of WoPan.

Properties:

- Config:      root_folder_id
- Env Var:     RCLONE_WOPAN_ROOT_FOLDER_ID
- Type:        string
- Default:     "0"

#### --wopan-encoding

The encoding for the backend.

See the [encoding section in the overview](/overview/#encoding) for more information.

Properties:

- Config:      encoding
- Env Var:     RCLONE_WOPAN_ENCODING
- Type:        Encoding
- Default:     Slash,LtGt,Question,Asterisk,Del,Ctl,InvalidUtf8,Dot

#### --wopan-description

Description of the remote.

Properties:

- Config:      description
- Env Var:     RCLONE_WOPAN_DESCRIPTION
- Type:        string
- Required:    false

## Limitations

### No hashes

WoPan does not expose file hashes, so rclone can only compare size and
modification time when syncing.

### Modification times cannot be set

The server stamps files with the creation time on upload and there is no way
to change it afterwards. Modification times are read-only and have one second
precision (China time zone).

### No zero-length files

The WoPan upload API rejects zero-length parts, so uploading empty files
fails with an error. This is a server-side limitation.

### No overwrite upload

WoPan does not support overwriting a file in place. When updating an existing
file, rclone deletes the old file first and then uploads the new one, so a
failed upload leaves the old file removed.

### Sequential chunked upload

Files are uploaded in 8 MiB chunks sequentially. There is no parallel chunked
upload and no resumable upload, so large file uploads are limited to a single
stream.

### Character restrictions

The server rejects names containing `?`, `*`, `<` and `>` (and names that are
not valid UTF-8). The default encoding replaces these characters with
full-width equivalents so such files can still be synced.
