# 自用 fork 的维护方式

本仓库是 `rclone/rclone` 的长期自用 fork. 自用功能留在 `zen`, 上游更新通过 merge 合入 `zen`, 不计划向上游提交代码. 优先减少上游核心层差异, 同时允许按已批准的自用需求修改功能.

## 分支与远端

`zen` 用于日常开发、默认分支与发布. `origin` 指向 `XyzenSun/rclone`, 自用提交推送到这里. `upstream` 指向 `https://github.com/rclone/rclone.git`, 只用于获取更新, 其 push URL 设置为 `disabled://upstream` 以阻止误推送. 本地 Git 配置不会随仓库提交传播, 新克隆需要重新配置:

```bash
git remote add upstream https://github.com/rclone/rclone.git
git remote set-url --push upstream disabled://upstream
```

GitHub 默认分支需要在仓库 Settings 中改为 `zen`, 本地添加 remote 不会修改该设置. 历史 `master` 已有 fork 的发布脚本提交, 当前保留原样, 不作为纯上游镜像或同步中转使用. 不自动 reset、删除或改写其历史.

## 获取上游更新

同步前检查分支、暂存区与工作区. 有未提交改动时暂停 merge, 先由用户决定如何保存或处理. 不自动 stash、reset 或覆盖工作区文件.

工作区干净并获得同步批准后, 使用以下顺序:

```bash
git status --short --branch
git switch zen
git pull --ff-only origin zen
git fetch --no-tags upstream
git log --oneline zen..upstream/master
git diff --stat zen...upstream/master
git merge upstream/master
```

先同步自己的 `origin/zen`, 再检查上游新增提交与实际差异. `git pull --ff-only` 遇到本地与远端分叉时会停止, 此时先分析分叉原因. `git fetch --no-tags upstream` 获取上游分支更新, 避免混入暂时不需要的 tag. 上游 `v*` tag 如有验证需要可单独获取, 不覆盖已有 tag.

`git merge upstream/master` 保留已有自用提交与已发布历史. 冲突需要逐项理解双方改动, 不批量选择 ours/theirs. 程序设计或行为兼容存在分歧时先与用户确认. 默认分支变化不影响这里明确指定的 `upstream/master` 同步来源.

merge 可能直接产生合并提交, 因此执行前需要获得包含 Git 写操作的批准并读取 Git 规范. 不通过 rebase 或 force push 整理已发布的 `zen` 历史. 若决定放弃发生冲突的合并, 先确认再执行 `git merge --abort`.

## 合并后的验证

根据上游实际变更评估验证范围. 自用 backend 与相关接口有变化时, 做构建、对应纯函数测试与必要的真实凭证验证. 只改文档时不跑云端测试. 上游大范围更新或跨大版本更新需要单独确认全量测试范围, 不默认连跑完整 fstests.

真实凭证只通过环境变量注入, 不写入文档、配置样本或测试文件. 云端测试前估算请求配额与测试数据残留, 不把平台能力限制误判为实现缺陷. 合并后的变更在验证完成前不发布.

需要修复自用代码时将修复与上游合并分开提交, 便于区分同步来源与自用调整. 验证与提交检查完成后, 获得 push 批准再推送:

```bash
git push origin zen
```

添加 remote、合并更新、解决冲突、commit 与 push 各阶段都遵循用户确认的范围, 不因前一阶段完成而自动扩大操作范围.

## 发布与安装

`VERSION` 跟随上游, fork 不单独改写它. 保留 `.github/workflows/zen-release.yml` 的现有机制: `zen-v*` tag 触发 GitHub Release, 发布构建附加 `-zen` 标识; 手动 `workflow_dispatch` 构建附加 `-zen.dev.<commit>` 标识, 只上传 Actions artifact. 发布 tag 指向已验证的 `zen` 提交, 与官方 `v*` tag 区分, 不移动或覆盖已发布 tag.

安装脚本从本 fork 的最新 GitHub Release 下载固定名产物. 脚本入口使用 `zen` 分支, 后续调整不需要先合入 `master`:

```bash
sudo -v
curl -fsSL https://raw.githubusercontent.com/XyzenSun/rclone/zen/zen-docs/install.sh | sudo bash
```

日常推送 `zen` 不会自动创建 Release. 修改 GitHub 默认分支也不会替代现有 tag 发布触发条件. 发布方式需要变化时, 单独确认 workflow 与安装脚本的调整范围.
